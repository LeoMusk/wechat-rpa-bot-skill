## 1. 文档说明

本文用于指导外部 AI Agent、支持 MCP 的应用或自建智能体平台，接入 YoBot 客户端提供的微信自动化能力。能力覆盖账号查询、消息发送、联系人与群聊、批量推送、朋友圈、自动添加好友和聊天记录查询。

调用方向为：

```text
外部 Agent / MCP 客户端 → 本机微信 RPA MCP 服务 → 微信桌面客户端或 RPA 本地数据
```

外部 Agent 根据用户需求选择工具并构造参数，RPA 服务执行具体操作。本文重点说明使用场景、入参、约束和调用示例，不逐项固定业务返回结构。

本文中的 **payload** 指工具返回的业务数据。Agent 可以根据实际 payload 解析结果，但不能自行决定服务端返回什么字段，也不能省略成功、失败与执行状态的判断。**输入参数仍须遵守工具的 `inputSchema`**，具体见第 3 节。

## 2. 接入方式

### 2.1 使用前提

1. YoBot 客户端已运行，微信 RPA 插件已就绪，相关业务授权有效。

2. 客户端「对外开放」开关已开启，页面显示连接正常。

3. 涉及微信界面操作时，目标微信账号已登录并由 RPA 初始化、托管。

4. MCP 调用方能访问运行 RPA 的电脑。默认地址中的 `127.0.0.1` 指这台电脑；云端 Agent 或另一台电脑不能直接使用该地址。

服务启动、微信初始化和插件维护由 YoBot 客户端负责。外部接入方从「对外开放」页面复制接入配置即可。

### 2.2 MCP 配置示例

```json
{
  "mcpServers": {
    "wechat-rpa": {
      "url": "http://127.0.0.1:9922/mcp",
      "headers": {
        "Authorization": "Bearer <从客户端复制的连接令牌>"
      }
    }
  }
}
```

`wechat-rpa` 为示例服务别名，可以使用客户端生成的名称。各宿主的配置格式可能不同；如需手动选择传输类型，请选择 **Streamable HTTP**，并按宿主要求重载 MCP 配置。

连接令牌用于 MCP 鉴权，不是微信账号、激活码或模型 API Key。重新生成令牌后，需要更新所有接入方的配置。

### 2.3 建议调用顺序

```text
建立 MCP 连接并完成初始化
  → tools/list 获取工具与 inputSchema
  → wechat_list_instances 查询可用微信账号
  → tools/call 调用具体业务工具
  → 解析结果；后台任务继续查询状态或日志
```

协议初始化、版本协商和连接管理通常由宿主或 MCP SDK 完成。`/mcp` 是统一端点，工具名不是 HTTP 路径。

## 3. 通用调用约定

### 3.1 请求结构

完成 MCP 初始化后，一次文字发送的 `tools/call` 请求示例如下：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "wechat_send_message",
    "arguments": {
      "user": "文件传输助手",
      "message": "MCP 接入测试",
      "account_id": "<可用微信账号ID>"
    }
  }
}
```

后文的 JSON 示例均只展示 **`arguments` 内容**。无参数工具传 `{}`。不要额外包装成 `{"payload": {...}}`，也不要把其他工具或 REST 接口的字段直接套用到 MCP 工具中。

### 3.2 参数规则

|项目|约定|
|---|---|
|参数名称|大小写与下划线必须保持一致。`accountId` 与 `account_id` 不能互换|
|必填|“是”为每次调用必填；“条件必填”为满足指定场景时必填；“否”为可省略|
|可选参数|无需设置时建议省略；不要用空字符串或 `0` 代替“不设置”|
|发送账号|`account_id`、`accountId`、`account_ids` 均来自 `wechat_list_instances`，不是接收人的微信号|
|接收对象|`user`、`targets`、`friends`、`target_group` 使用微信中的准确好友名称、备注名或群名，以对应工具说明为准|
|多账号|涉及发送、发布或查询账号数据时，建议明确传入目标账号。省略可选账号参数时由后端选择默认实例|
| 文件路径 | 路径必须在 **RPA 所在电脑** 上存在且可读。JSON 中 Windows 反斜线写成 `\\`，例如 `C:\\Materials\\产品介绍.pdf` |
| 数组 | 传 JSON 数组，例如 `["客户A", "客户B"]`，不要传逗号拼接的字符串 |
| 时间 | `schedule_time` 使用 RPA 所在电脑的本地时间，不带时区；调用方需先完成时区换算 |
| 示例占位符 | `<可用微信账号ID>`、`<真实任务ID>` 等均需替换为查询返回的真实值 |

### 3.3 返回结果与执行状态

工具通过 MCP 返回结果，业务 payload 可能是对象、数组，或 MCP 文本内容中的 JSON；支持结构化结果的宿主也可能提供结构化数据。接入方应按实际结果解析，保留未知字段的兼容性。

无需为每个工具绑定完整的固定返回模型，但至少应遵循以下规则：

- **区分协议错误与业务失败。** 先检查 MCP 调用是否报错，再检查业务 payload。多数工具存在 `success`、`httpStatus`、`data` 包装；业务对象内还可能有自己的 `success`、`status`、`error` 或 `message`。HTTP 成功或外层 `success=true` 不一定代表业务成功。

- **区分提交成功与执行完成。** 群发、自动添加好友等工具可能只完成任务创建。应保存返回的任务标识，再查询任务状态或执行日志。

- **区分空结果与读取失败。** 查询成功且列表为空，才能说明当前没有匹配数据；读取失败不能解释为“没有联系人”“没有音色”或“没有历史”。

- **避免重复发送。** 文字发送若返回 `delivery_state="unknown"` 或 `retryable=false`，先核对最近消息；请求超时也不能据此认定没有发送成功。

## 5. 工具接口详情

### 5.1 查询可用微信账号 `wechat_list_instances`

**使用场景：** 接入验证、多账号选择，以及其他工具调用前获取发送账号标识。返回当前已登录、已初始化且可执行 RPA 操作的微信实例。

**入参：** 无。

```json
{}
```

**调用说明：** 使用返回的 `account_id` 作为后续账号参数。没有可用实例时，应在客户端检查微信登录、托管状态；不要自行拼接账号 ID。

### 5.2 发送文字消息 `wechat_send_message`

**使用场景：** 给已知好友或群聊发送通知、客服回复、提醒等文字消息。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`user`|string|是|接收好友的准确名称、备注名，或准确群名|
|`message`|string|是|要发送的文字内容|
|`account_id`|string|否|发送方微信账号 ID；多账号时建议明确指定|

```json
{
  "user": "客户张先生",
  "message": "您好，您需要的资料已经整理完成。",
  "account_id": "<可用微信账号ID>"
}
```

**调用说明：** 已知准确收件人名称时，无需先同步通讯录。遇到发送状态不确定，应通过 `wechat_fetch_latest_messages` 核对后再决定后续动作，避免重复发送。

### 5.3 发送文件 `wechat_send_file`

**使用场景：** 向好友或群聊发送本地图片、视频、PDF、办公文档等文件。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`user`|string|是|接收好友名称、备注名或群名|
|`file_path`|string|是|RPA 所在电脑上的文件绝对路径；一次一个文件|
|`account_id`|string|否|发送方微信账号 ID|

```json
{
  "user": "项目沟通群",
  "file_path": "C:\\Materials\\产品介绍.pdf",
  "account_id": "<可用微信账号ID>"
}
```

**调用说明：** 当前参数接收本地路径，不是文件 URL 或 Base64。多个文件需分别调用；远端文件应先由调用方准备到 RPA 可访问的本地路径。

### 5.4 发送语音消息 `wechat_send_voice`

**使用场景：** 发送真实微信语音气泡，可使用已有 MP3，也可将文字按已配置的克隆音色合成后发送。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`user`|string|是|接收好友名称、备注名或群名|
|`audioPath`|string|条件必填|方式一：本地 MP3 的绝对路径|
|`audioFilename`|string|条件必填|方式二：RPA `voice_greetings` 目录内已存储的 MP3 文件名，不含目录|
|`text`|string|条件必填|方式三：待合成文字，必须与 `voiceId` 一起传入|
|`voiceId`|string|条件必填|方式三：克隆音色 ID，必须来自 `wechat_list_voices`|
|`speed`|number|否|仅文字合成时使用。默认 `1.0`，后端限制在 `0.5`～`2.0`|
|`accountId`|string|否|发送方微信账号 ID，注意此处为驼峰命名|

本地音频示例：

```json
{
  "user": "客户张先生",
  "audioPath": "C:\\Materials\\欢迎语.mp3",
  "accountId": "<可用微信账号ID>"
}
```

文字合成示例：

```json
{
  "user": "客户张先生",
  "text": "您好，我来为您介绍一下本次服务安排。",
  "voiceId": "<查询得到的音色ID>",
  "speed": 1.0,
  "accountId": "<可用微信账号ID>"
}
```

**调用说明：** 三种音频来源选一种。若同时传入，当前处理优先级为 `audioPath` → `audioFilename` → `text + voiceId`。发送语音需要微信版本不低于 4.1.9，并安装 VB-Cable 虚拟音频驱动；文字合成还需配置可用语音服务。环境或合成失败时，按实际结果处理，不应把普通 MP3 附件描述为语音气泡。

### 5.5 查询可用音色 `wechat_list_voices`

**使用场景：** 在文字合成语音前，查询当前可用的克隆音色，取得 `voiceId`。

**入参：** 无。

```json
{}
```

**调用说明：** 仅返回可用状态的音色。可将音色显示名称提供给用户选择；查询失败不等于没有音色，音色 ID 不应由 Agent 编造。

### 5.6 读取当前窗口消息 `wechat_fetch_latest_messages`

**使用场景：** 查看某个会话当前窗口能读取到的最近消息，或核对一条消息是否已发送。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`sessionName`|string|是|准确好友名称、备注名或群名|
|`accountId`|string|否|所属微信账号 ID，注意此处为驼峰命名|

```json
{
  "sessionName": "项目沟通群",
  "accountId": "<可用微信账号ID>"
}
```

**调用说明：** 依赖正在运行的微信，只返回窗口消息快照，不提供持续监听，也不保证完整历史。群聊回顾应使用第 5.25 节的历史查询工具。

### 5.7 同步好友或群聊 `wechat_sync_contacts`

**使用场景：** 主动刷新通讯录；新好友、新群未出现在已有查询结果时更新本地数据。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`type`|string|是|`friend`：同步好友；`group`：同步群聊|
|`account_id`|string|是|要同步的微信账号 ID|

```json
{
  "type": "group",
  "account_id": "<可用微信账号ID>"
}
```

**调用说明：** 同步需要操作微信，可能耗时约两分钟或更久。该工具返回同步结果，不直接返回联系人清单；同步成功后再调用 `wechat_get_contacts` 或 `wechat_get_groups`。不要把同步作为每次发送前的固定步骤。

### 5.8 查询好友通讯录 `wechat_get_contacts`

**使用场景：** 查找联系人、按标签筛选好友，或为后续业务取得联系人名称和标识。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`tag`|string|否|标签名称；`untagged` 表示未分组，`全部` 表示全部好友|
|`keyword`|string|否|按联系人显示名称进行关键词匹配，英文不区分大小写|
|`account_id`|string|否|查询哪个微信账号的通讯录|

```json
{
  "keyword": "张",
  "account_id": "<可用微信账号ID>"
}
```

**调用说明：** 查询已同步数据，不会自动刷新微信通讯录。当前实现中同时传入 `tag` 和 `keyword` 时，**标签筛选优先，关键词不再叠加过滤**；需要组合筛选时，可先按标签查询，再由调用方过滤名称。

### 5.9 查询群聊 `wechat_get_groups`

**使用场景：** 搜索已同步群聊，确认发送消息或邀请入群时使用的准确群名。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`keyword`|string|否|群名关键词，英文不区分大小写；省略则不按名称筛选|
|`account_id`|string|否|所属微信账号 ID|

```json
{
  "keyword": "项目",
  "account_id": "<可用微信账号ID>"
}
```

**调用说明：** 返回已同步的群聊，不包含群成员查询能力。数据过旧时，先使用 `wechat_sync_contacts`，并设置 `type="group"`。

### 5.10 邀请好友进群 `wechat_invite_to_group`

**使用场景：** 将一个或多个已有微信好友邀请到已存在的群聊。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`friends`|array\<string\>|是|待邀请好友的准确名称列表，不能为空|
|`target_group`|string|是|已存在的目标群准确名称，不能为空|
|`account_id`|string|是|执行邀请的微信账号 ID|

```json
{
  "friends": ["客户张先生", "客户李女士"],
  "target_group": "产品体验群",
  "account_id": "<可用微信账号ID>"
}
```

**调用说明：** 调用前应由外部 Agent 取得用户对邀请对象和目标群的确认。这是邀请已有好友入群，不是创建群聊或添加新好友；实际结果以微信执行反馈为准。

### 5.11 创建群发任务 `wechat_mass_sending`

**使用场景：** 向指定好友、群聊或标签覆盖的对象批量发送消息，可立即执行或定时执行。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`tags`|array\<string\>|条件必填|好友或群标签列表；可用 `untagged` 表示未分组。与 `targets` 至少提供一个非空列表|
|`targets`|array\<string\>|条件必填|准确好友名称或群名列表；可以与 `tags` 同时传入，目标合并去重|
|`text`|string|条件必填|直接发送的文本文案，支持 `{name}` 收件人名称占位符；与 `greeting_group` 二选一|
|`greeting_group`|string|条件必填|已配置的话术组名称或 ID；使用该组的内容策略，与 `text` 二选一|
|`schedule_time`|string|否|本地时间，格式 `YYYY-MM-DD HH:mm`；省略即立即执行。必须晚于当前时间，且不超过未来 30 天|
|`batch_size`|integer|否|每批目标数量，默认 `10`；当前后端将批次大小限制在 `2`～`500`|
| `send_interval` | string | 否 | 单条发送间隔范围，单位为**秒**，格式如 `"3-8"`；省略时当前后端默认 `"3-8"` |
| `account_id` | string | 否 | 执行群发的微信账号 ID |

按明确对象立即发送：

```json
{
  "targets": ["客户张先生", "客户李女士"],
  "text": "{name}，您好，本周的服务安排已更新。",
  "batch_size": 10,
  "send_interval": "3-8",
  "account_id": "<可用微信账号ID>"
}
```

按标签定时发送，使用已有话术组：

```json
{
  "tags": ["产品体验用户"],
  "greeting_group": "活动提醒",
  "schedule_time": "2026-10-07 10:00",
  "send_interval": "5-10",
  "account_id": "<可用微信账号ID>"
}
```

**调用说明：**

- 这是实际创建任务的接口，**不是预览接口**。调用前由外部 Agent 确认发送账号、目标范围、文案或话术组、执行时间和间隔。

- 当前 MCP 入参不包含 `confirmed`、`confirmationId`；不要套用客户端内部工具的两阶段确认参数。

- `send_interval` 在此接口使用以秒为单位的范围字符串，不要传 `"3-8秒"` 或误当成分钟。

- 一次群发可能拆成多个批次并返回多个任务标识。保存实际任务标识，通过 `wechat_list_mass_sending_tasks` 跟踪；创建成功不代表所有对象已发送成功。

- 示例定时时间仅用于说明格式，实际调用须改为未来 30 天内的时间。

### 5.12 查询群发任务 `wechat_list_mass_sending_tasks`

**使用场景：** 查看批量推送执行情况，获取暂停、恢复或取消时所需的真实任务 ID。

**入参：** 无。

```json
{}
```

**调用说明：** 关注每个任务的实际 `status` 与进度。当前结果可能按 `running`、`pending` 分组，其中 `pending` 容器收纳所有非 `running` 任务，不能仅凭容器名判断任务仍在等待执行。

### 5.13 暂停群发任务 `wechat_pause_mass_sending_task`

**使用场景：** 暂停指定群发任务，待业务确认后再恢复。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`task_id`|string|是|群发任务 ID，从创建结果或群发任务列表取得|

```json
{
  "task_id": "<真实群发任务ID>"
}
```

**调用说明：** 暂停不会撤回已发送内容。操作后重新查询任务状态，确认暂停结果。

### 5.14 恢复群发任务 `wechat_resume_mass_sending_task`

**使用场景：** 恢复此前暂停的群发任务。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`task_id`|string|是|待恢复的真实群发任务 ID|

```json
{
  "task_id": "<真实群发任务ID>"
}
```

**调用说明：** 恢复操作会继续执行消息发送。不要通过重新调用 `wechat_mass_sending` 代替恢复，否则可能创建重复群发。

### 5.15 取消群发任务 `wechat_cancel_mass_sending_task`

**使用场景：** 取消不再需要继续执行的群发任务。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`task_id`|string|是|待取消的真实群发任务 ID|

```json
{
  "task_id": "<真实群发任务ID>"
}
```

**调用说明：** 已发送的消息无法通过该工具撤回。上述暂停、恢复、取消接口均以 `task_id` 为输入，不接收 `campaign_id`；多批次推送应检查实际关联任务状态，不应把单次调用成功直接解释为全部批次已处理。

### 5.16 查询 RPA 任务 `wechat_get_tasks`

**使用场景：** 查看调度器中当前存在的任务、任务类型、计划执行时间与进度，排查任务是否已创建。

**入参：** 无。

**调用说明：** 这是调度任务列表，不是完整历史执行日志。群发进度优先使用 `wechat_list_mass_sending_tasks`；朋友圈和加好友结果使用各自日志工具。当前后端可能使用约 3 秒的任务列表缓存，不必高频重复查询。

### 5.17 立即发布朋友圈 `wechat_post_moment`

**使用场景：** 立即发布一条文字、图片或视频朋友圈，并可按微信标签设置可见范围。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`content`|string|条件必填|朋友圈文案，默认空字符串；与有效素材至少提供一项|
|`files`|array\<string\>|条件必填|本地图片或视频的绝对路径列表；无素材时省略或传空数组|
|`account_id`|string|否|发布朋友圈的微信账号 ID|
|`visibility`|string|否|`public`：公开，默认值；`include`：仅标签内好友可见；`exclude`：标签内好友不可见|
|`visibility_tags`|array\<string\>|条件必填|`include` 或 `exclude` 时必须提供的非空微信标签名称列表|

公开发布文字：

```json
{
  "content": "今天的产品体验活动已经开始，欢迎交流。",
  "account_id": "<可用微信账号ID>"
}
```

发布图文，仅指定标签好友可见：

```json
{
  "content": "本周产品体验安排。",
  "files": ["C:\\Materials\\活动海报.jpg"],
  "account_id": "<可用微信账号ID>",
  "visibility": "include",
  "visibility_tags": ["产品体验用户"]
}
```

**调用说明：** `visibility="public"` 时不能附带非空 `visibility_tags`；`include` 和 `exclude` 不能省略标签。素材必须预先存在且符合微信可发布要求。该工具立即执行，不接受定时参数；不能据此创建周期发布计划。

### 5.18 查询朋友圈发布任务 `wechat_list_moment_post_tasks`

**使用场景：** 查看已有的定时朋友圈发布任务及执行状态。

**入参：** 无。

**调用说明：** 可查询此前在客户端配置的任务。本文列出的工具提供该查询入口，但未包含创建、取消定时朋友圈任务的工具；如当前版本开放了更多工具，以 `tools/list` 为准。

### 5.19 查询朋友圈发布记录 `wechat_get_moment_post_logs`

**使用场景：** 查看定时朋友圈任务的历史执行记录，确认是否发布成功及失败原因。

**入参：** 无。

**调用说明：** 这是任务执行记录，不是微信朋友圈内容流。当前工具不接受任务 ID、日期或分页参数；如需筛选，按实际返回记录在调用方处理。

### 5.20 查询待添加好友名单 `wechat_get_friend_list`

**使用场景：** 查询已经导入 RPA 的加好友名单，筛选待添加、已处理或失败的对象。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`status`|string|否|名单状态：`pending` 待添加、`added` 已执行添加、`failed` 添加失败、`unknown` 状态未知、`already` 已是好友|
|`tag`|string|否|按导入名单中的标签名称筛选；可与 `status` 同时使用|

```json
{
  "status": "pending",
  "tag": "活动报名"
}
```

**调用说明：** 该名单不同于 `wechat_get_contacts` 的现有好友通讯录。当前最多返回 1000 条，无分页和 `account_id` 参数；返回条数不能作为全部待添加数量，应使用第 5.21 节工具计数。名单记录的 `added` 不应单独作为对方已通过好友验证的证明。

### 5.21 查询待添加好友数量 `wechat_get_friend_remaining_count`

**使用场景：** 自动添加前检查是否还有待处理名单，或查看当前默认账号今日已添加数量。

**入参：** 无。

**调用说明：** 主要业务信息为 `remaining`（名单中待添加数量）与 `today_added`（默认微信账号今日已添加数量）。不支持传入账号参数，不应将其解释为多个账号合计的今日添加数量。

### 5.22 开关自动添加好友 `wechat_toggle_auto_add_friend`

**使用场景：** 基于已经导入的名单启动自动添加好友，配置每日上限、执行间隔和多账号轮换，或停止该任务。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`enabled`|boolean|是|`true` 启动；`false` 停止|
|`max_friends_per_day`|integer|否|单个执行账号每日添加上限；未配置历史值时默认 `10`|
| `interval` | integer | 否 | 每轮任务检查、执行的间隔，单位为**分钟**；未配置历史值时默认 `60` |
| `batch_size` | integer | 否 | 每轮最多处理的名单数量；未配置历史值时默认 `1` |
| `verify_message` | string | 否 | 发起好友申请时使用的验证消息；未配置历史值时默认空字符串 |
| `multi_cycle_enabled` | boolean | 否 | 是否启用多账号轮换；MCP 参数默认 `false`，实际生效值受历史配置合并影响，见下文 |
| `account_ids` | array\<string\> | 否 | 多账号轮换使用的账号 ID 列表，来自 `wechat_list_instances`；单账号模式使用当前默认实例 |

启动示例：

```json
{
  "enabled": true,
  "max_friends_per_day": 10,
  "interval": 60,
  "batch_size": 1,
  "verify_message": "您好，我是本次活动的服务顾问。",
  "multi_cycle_enabled": true,
  "account_ids": ["<可用微信账号ID-A>", "<可用微信账号ID-B>"]
}
```

停止示例：

```json
{
  "enabled": false
}
```

**调用说明：**

- 启动前由外部 Agent 取得用户确认，并确保已经导入待添加名单；本文尚未收录名单导入工具的参数定义，可在客户端导入，或先通过 `tools/list` 确认当前版本是否提供相应工具及其 `inputSchema`。

- 启动后会安排立即执行并按间隔循环；`enabled=true` 成功不表示名单已全部处理。

- 当前后端按“传入有效值 → 历史配置 → 默认值”合并参数，并使用真假值回退。因此 `0`、空字符串、空数组不能可靠地清空历史配置；历史已开启多账号轮换时，传 `multi_cycle_enabled=false` 也可能沿用历史值。

- 启动后应核对返回的实际生效 `params`。需要清空历史设置或关闭历史轮换配置时，应在客户端设置中修改；停止整个自动添加任务使用 `enabled=false`。

### 5.23 查询添加好友记录 `wechat_get_add_friend_logs`

**使用场景：** 检查自动加好友的执行结果，排查失败或未完成的名单项。

**入参：** 无。

**调用说明：** 读取后端已有的加好友执行日志。当前不接受账号、日期或分页参数，需要按实际返回信息筛选；不能将任务启动成功直接替代逐项执行结果。

### 5.24 查询已保存会话 `wechat_list_sessions`

**使用场景：** 做聊天回顾、群聊总结前，查找有本地历史记录的会话名称、会话标识及所属账号。

**入参：** 无。

**调用说明：** 查询本地已积累的历史会话，不是微信当前会话窗口列表。当前后端按有效微信实例汇总会话；未列出某个会话，不能直接断言磁盘上从未保存过该会话记录。

### 5.25 查询会话历史消息 `wechat_get_session_messages`

**使用场景：** 读取已保存的群聊或私聊记录，供外部 Agent 总结、回顾、提取事项。

|参数|类型|必填|含义及约束|
|---|---|---|---|
|`sessionName`|string|是|准确会话名称或会话 ID；优先使用 `wechat_list_sessions` 返回的值|
|`account_id`|string|否|历史记录所属微信账号 ID；跨账号同名会话应明确指定|
|`since`|string|否|起始时间，格式为 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM`；省略则不按起点过滤|
|`limit`|integer|否|保留符合条件的最近 N 条消息，应传正整数；省略则不限制条数|

```json
{
  "sessionName": "项目沟通群",
  "account_id": "<可用微信账号ID>",
  "since": "2026-10-01 00:00",
  "limit": 200
}
```

**调用说明：**

- 读取 RPA 已保存到本机的历史，不会自动补抓微信全部历史，也不会触发实时采集。

- 工具先读取记录，再应用 `since`，最后保留最近 `limit` 条。当前时间筛选基于消息时间字段的字符串比较，不支持自然语言日期或自动时区转换。

- `limit` 是读取后的结果裁剪，不是分页游标；当前没有 `offset`、`cursor`、`until` 参数。

- 总结前核对实际返回消息的起止时间和数量，说明记录覆盖范围；部分历史不能表述为完整群聊记录。

## 6. 常见业务调用流程

### 6.1 给指定客户发送资料

```text
wechat_list_instances → 选择发送账号
  → 确定客户准确名称
  → wechat_send_message 发送说明
  → wechat_send_file 发送本地资料
  → 分别检查文字和文件的业务结果
```

仅在收件人名称不明确时调用 `wechat_get_contacts` 辅助查找，不需要每次都同步通讯录。

### 6.2 按标签批量推送通知

```text
选择发送账号，核对标签及目标范围
  → 确认文案或已有话术组、执行时间、发送间隔
  → 用户确认
  → wechat_mass_sending 创建任务
  → 保存返回的任务标识
  → wechat_list_mass_sending_tasks 查询进度
  → 按需暂停、恢复或取消具体任务
```

通知发送结果应根据实际任务状态汇总，不能仅依据创建接口成功。

### 6.3 启动自动添加好友

```text
在客户端导入名单
  → wechat_get_friend_list 查看待处理对象
  → wechat_get_friend_remaining_count 查看剩余数量
  → 用户确认执行范围、账号与参数
  → wechat_toggle_auto_add_friend 启动
  → 核对实际生效参数
  → wechat_get_add_friend_logs 查看执行结果
  → 需要停止时设置 enabled=false
```

### 6.4 总结某个群聊

```text
wechat_list_sessions → 定位准确会话和所属账号
  → wechat_get_session_messages 读取指定范围记录
  → 核对覆盖时间和条数
  → 外部 Agent 生成总结与待办
```

若只想知道当前窗口正在聊什么，使用 `wechat_fetch_latest_messages`。

## 7. 常见问题与处理

|现象|判断与处理|
|---|---|
|MCP 无法连接|检查客户端是否运行、RPA 是否就绪，以及调用方是否能访问这台电脑的 `127.0.0.1:9922`|
|MCP 返回 401|检查 `Authorization: Bearer` 及连接令牌；令牌重置后重新复制配置|
|MCP 返回 404 / `MCP is disabled`|检查「对外开放」是否开启及地址是否为 `/mcp`；页面提示需升级时更新插件|
|业务返回授权错误或 403|检查客户端登录和微信 RPA 业务授权状态；连接成功不代表业务授权校验已通过|
|工具不存在或参数校验失败|重新获取 `tools/list`；核对工具模式、版本、必填字段、类型和大小写|
|没有可用微信账号|在客户端检查微信是否登录、是否已初始化及是否退出托管|
|联系人或群聊缺失|确认账号与筛选条件；确需更新时同步对应好友或群聊后再查询|
|本地文件不存在|确认路径属于 RPA 所在电脑，且文件已准备完成；不能直接传云端容器路径|
|语音发送失败|检查微信版本、虚拟音频驱动、音频文件、音色和语音服务配置|
|群发任务已创建但尚未发送完|查询群发任务的真实状态、时间和进度；不要重复创建同样的群发|
|自动加好友提示没有名单|先在客户端导入名单；该功能不会把通讯录好友自动当作待添加名单|
|自动加好友参数与预期不一致|检查返回的生效参数与历史配置，尤其是空值和多账号轮换设置|
|历史记录为空或覆盖不足|确认会话标识、账号和时间范围，以及 RPA 是否已采集并保存对应记录|
|发送或发布请求超时|先查询消息、任务或实际发布结果；超时不能证明操作未发生，不宜直接重复执行|
