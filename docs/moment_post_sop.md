# 自动发朋友圈 SOP (Standard Operating Procedure)

当用户要求「帮我准备 / 安排一段时间的朋友圈」「自动发朋友圈」「做一个发圈计划」「批量准备发圈素材」时,Agent **必须严格按本 SOP** 与用户多轮沟通、按规范落盘素材、再创建定时发圈任务,最后确认闭环。

> **最终目标**:经过与用户的多轮沟通,按 RPA 素材规范在对应目录创建好素材组,成功调用接口创建**定时循环发圈任务**,并查询确认任务已创建。

> ⚠️ `wechat_post_moment` 只能**立即发一条**,用于临时测试,**不是**本 SOP 的替代品。本 SOP 产出的是一个会按定时规则循环执行的发圈计划。

---

## 0. 核心概念:素材目录规范

发圈任务的素材按**两级目录**组织,这是整个 SOP 的落盘标准:

```
<计划文件夹>/                  ← plan 文件夹,由 wechat_create_moment_plan 创建并返回绝对路径
  ├─ 01_周一/                  ← 素材组 = 一条完整朋友圈
  │    ├─ 文案.txt             ← 文案,UTF-8 编码,一个素材组放一个 .txt
  │    ├─ a.jpg                ← 图片/视频,直接平铺在素材组目录里
  │    └─ b.png
  ├─ 02_周二/
  │    ├─ 文案.txt
  │    └─ c.jpg
  └─ ...
```

规则:
- **一个素材组 = 一条朋友圈**。发圈任务每次触发挑一个素材组发布。
- 素材组目录里 **必须有且只放一个 `.txt`** 文案文件(任务取排序后的第一个 `.txt`)。
- 媒体文件直接平铺在素材组目录里,**不要再建子目录**。
- 媒体格式白名单:`.png .jpg .jpeg .bmp .gif .mp4 .mov .avi`。其他格式无效。
- 单个素材组的图片建议 **≤ 9 张**(微信朋友圈上限)。
- 素材组**目录名带序号前缀**(如 `01_`、`02_`):`publishMode=sequence`(按序发布)按目录名字母序选组,带序号才能控制发布顺序。

---

## 文件操作约束(务必遵守)

本 SOP 由 Agent 用自身的文件工具直接创建目录、写文案、复制图片。**严格限定**操作范围:

- ✅ 只在 `wechat_create_moment_plan` 返回的 `path`(计划文件夹)**内部**创建素材组目录、写入 `.txt`、复制图片。
- ✅ 用户提供的原始图片一律 **复制(copy)** 进素材组,**不要移动(move)**,保留用户原文件。
- ❌ **绝不**删除计划文件夹以外的任何文件 / 目录。
- ❌ **绝不**修改或覆盖用户原始素材文件。
- 如需删除自己刚建错的素材组目录,只能删计划文件夹**内部**自己创建的内容,且应先向用户说明。

## 1. 决策总览

```
发圈计划请求
  │
  ├─ Step 1  多轮沟通:确认发圈目标、风格、频率、账号、图片来源
  ├─ Step 2  批量生成文案,与用户对齐风格
  ├─ Step 3  规划素材组:N 条文案 ↔ N 组图片
  ├─ Step 4  落盘:创建计划文件夹 + 逐组写文案.txt + 复制图片
  ├─ Step 5  创建定时发圈任务
  └─ Step 6  查询任务列表确认闭环,反馈用户
            (任一步失败 → 走「兜底」)
```

---

## Step 1: 多轮沟通,确认需求

发圈计划信息量大,**不要一次性追问**,自然地分轮问清以下要点:

1. **发圈目标 / 主题**:产品种草?生活日常?活动预热?品牌人设?
2. **覆盖范围**:准备多少条?覆盖多长时间(如「最近一周」= 7 条)?
3. **文案风格**:口语化还是正式?字数大概多少?是否要 emoji / 话题标签 `#xx#`?
4. **执行频率**(决定任务参数):
   - 每天发还是只在工作日 / 指定周几发(`cycle` = `daily` / `weekly`)。
   - 每天发一条固定时间(`execMode=fixed`),还是一个时间段内发多条(`execMode=range`)。
5. **发圈微信账号**:调用 `wechat_list_local_users` 列出本地账号,与用户确认用哪个 `account_id`。**提醒用户:发朋友圈仅支持微信 4.0 以上版本。**
6. **图片素材(硬前提)**:让用户**提前准备好图片**,并提供图片所在的**本地目录或文件路径**。
   - 图片来源不限:用户自有的、或用 AI 生图技能生成的都可以。
   - 只要求是受支持的图片格式(见素材目录规范白名单)。
   - 若用户暂时没有图片,可以做纯文字朋友圈,但应先和用户确认是否接受无图。

---

## Step 2: 批量生成文案

按 Step 1 确认的目标、风格、条数,批量生成 N 条朋友圈文案。

- 先生成 **1~2 条样例**发给用户确认风格,对齐后再补齐其余。
- 每条文案就是一个素材组将要写入的 `.txt` 内容。
- 文案最终对齐版本要让用户确认,或明确告知用户「如需调整可随时说」。

---

## Step 3: 规划素材组与图片分配

- N 条文案 = N 个素材组。
- 与用户**确认每条文案配哪些图片**:可以让用户按顺序说明「第 1 条配 a.jpg、b.jpg…」,或约定一个规则。
- 确认每组图片数量 ≤ 9 张。
- 规划好素材组目录名(带序号:`01_xxx`、`02_xxx`…),序号顺序即希望的发布顺序。

---

## Step 4: 按规范落盘素材

1. 调用 `wechat_create_moment_plan({ plan_name: "<计划名>" })`,拿到返回的 `path`(计划文件夹绝对路径)。
2. 对每一条朋友圈,用 Agent 自身的文件工具:
   - 在 `path` 下创建素材组子目录(如 `<path>/01_周一/`)。
   - 在该子目录写入 `文案.txt`(UTF-8 编码),内容为对应文案。
   - 把用户指定的图片**复制**进该子目录。
3. 全部完成后,自查每个素材组:是否恰好一个 `.txt`、图片格式是否合法、图片是否 ≤ 9 张。

> 落盘期间严格遵守上文「文件操作约束」。

---

## Step 5: 创建定时发圈任务

调用 `wechat_create_moment_post_task`,参数按 Step 1 确认的频率组装:

| 参数 | 取值 |
| :--- | :--- |
| `name` | 计划名称 |
| `materialFolder` | Step 4 拿到的计划文件夹 `path` |
| `publishMode` | `sequence`(按目录名顺序) / `random`(随机) |
| `account` | Step 1 确认的发圈微信 `account_id` |
| `cycle` | `daily`(每天) / `weekly`(指定周几) |
| `weekDays` | `cycle=weekly` 时必传,日代码数组:`1`=周一 … `5`=周五,`6`=周六,`0`=周日 |
| `execMode` | `fixed`(每天固定时间发一条) / `range`(时间段内发多条) |
| `fixedTime` | `execMode=fixed` 时必传,`"HH:MM"` |
| `rangeStart` / `rangeEnd` / `postCount` | `execMode=range` 时必传:在 `rangeStart`~`rangeEnd` 内均匀发 `postCount` 条 |

> 该任务是**循环任务**:每次触发按 `publishMode` 取一个素材组发布。素材组发完会循环复用。

---

## Step 6: 确认闭环并反馈

1. `wechat_create_moment_post_task` 返回 `success: true` 与 `task_ids`。
2. 调用 `wechat_get_tasks` 获取全量调度任务,在结果中找到 `task_type` 为 `moment_post` 的新任务,确认其确实已被调度(可对照 `task_ids`)。
3. 向用户汇报:
   > 「已为您创建发圈计划「<计划名>」:共 N 个素材组,<频率描述,如 每个工作日 9:00 发一条>,发布方式 <按序/随机>,使用微信账号 <account>。任务已进入调度,首次执行时间约为 <next_run_time>。」

---

## 兜底

任一步骤失败时,不要反复重试:
- 把接口返回的错误信息**原样呈现**给用户,并指出卡在 SOP 的哪一步。
- 创建任务报错 `invalid_time` / `invalid_range`:检查 Step 5 的时间参数格式与大小关系。
- 创建任务报错素材相关:检查 Step 4 落盘是否符合「素材目录规范」(每组一个 `.txt`、媒体格式合法)。
- 提醒用户:发朋友圈仅支持微信 4.0 以上版本;若账号版本过低,任务即便创建也无法执行。
